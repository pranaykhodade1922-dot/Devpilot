---

## Reporting a Vulnerability

The DevPilot Security team takes security seriously. If you believe you have discovered a vulnerability in DevPilot Security itself, please help us protect the community by following responsible disclosure guidelines.

### Reporting Route

Please report potential security issues privately:
- **GitHub Private Vulnerability Reporting**: Use the **Security** tab of the official repository at [https://github.com/pranaykhodade1922-dot/Devpilot/security/advisories/new](https://github.com/pranaykhodade1922-dot/Devpilot/security/advisories/new) to submit an advisory report (subject to GitHub repository private vulnerability reporting being enabled).

Please **do not** report security vulnerabilities via public GitHub issues, discussions, or social media until maintainers have had an opportunity to investigate and release a fix.

---

## What to Include in Your Report

To help us triage and resolve the issue quickly, please provide:
1. **Description**: A clear explanation of the potential vulnerability.
2. **Impact**: An assessment of what an attacker could achieve.
3. **Reproduction Steps**: A minimal proof of concept (PoC) or step-by-step instructions.
4. **Environment**: Operating system, Node.js version, and DevPilot Security version.
5. **Mitigation**: Any suggested fixes or workarounds, if known.

---

## Responsible Disclosure & Policy

- Maintainers will investigate valid reports, determine severity, and prepare patches.
- We request that you provide reasonable time for maintainers to remediate the vulnerability before publishing details.
- Unauthorized testing against third-party production infrastructure or systems you do not own is strictly prohibited.
- Testing should be confined strictly to local mock environments.
